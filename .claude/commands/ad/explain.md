# 설명서 생성

대상을 **모르는 독자**가 읽고 이해하도록 설명서를 만든다. 코드 변경이든, 방금 끝낸 분석이든 같다.
판정하지 않는다 — 승인·finding·우선순위는 `/ad:code-review`의 몫이다. 시스템 정체를 그리는 것도 아니다 — 그건 `/ad:tldr`이다.

원안: Geoffrey Litt "explain-diff" 프롬프트 (배경·직관·코드·퀴즈 4단). 팀 규칙(한국어 md + mermaid, 마스킹, 인수인계)에 맞춰 번안하고 **남은 위험** 섹션을 추가했다.

트리거를 사용자 호출로 고정한 근거: 산출물이 파일 쓰기이고, "지금 설명서가 필요한가"는 사람이 판단한다. `disable-model-invocation: true`로 컨텍스트 부하를 0으로 둔다.

## 사용법

```text
/ad:explain                              # 현재 세션에서 방금 한 분석·조사를 대상으로
/ad:explain <PR URL | 브랜치 | 커밋범위 | 경로>
/ad:explain --analysis "<주제>"          # 코드가 아닌 분석·판단·조사 결과
/ad:explain --reader <리뷰어|신규합류자|기획·QA>
/ad:explain --html                       # md + 공유용 HTML 리더
/ad:explain --out <path>
```

## 모드

| 모드 | 대상 | 4번 섹션 제목 |
|---|---|---|
| `diff` | PR, 브랜치, 커밋 범위, 워킹트리 변경 | `무엇이 바뀌었나` |
| `analysis` | 조사 결과, 설계 판단, 레거시 구조 파악, DB 이관 검토, 장애 원인 | `무엇을 알아냈나` |

인자가 git 참조·PR URL이면 `diff`, 아니면 `analysis`. 인자가 없으면 현재 세션에서 직전에 다룬 대상을 `analysis`로 잡고 **한 줄로 확인받은 뒤** 진행한다.

## 산출 위치

`--out` > 대상 저장소에서 이미 gitignore된 디렉토리(`artifacts/`, `tmp/`, `.local/` 순) > `~/Documents/workspace/.explain/<repo>/`.
`.gitignore`를 고치지 않는다. 파일명은 `YYYY-MM-DD-explain-<slug>.md`.
vault·KB에 남길 문서라면 여기서 만들지 말고 [policies/knowledge-base-policy.md](../../../policies/knowledge-base-policy.md) 결정 트리를 따른다.

## 절차

1. **독자 지정.** 누가 읽는지 한 명 고른다(`--reader`, 기본 리뷰어). 독자가 정해져야 "어디부터 설명할지"가 정해진다.
   *완료 기준*: 그 독자가 **이미 아는 것**과 **모르는 것**을 각각 2개 이상 적었고, frontmatter `reader`에 남겼다. 나중에 "이 문서 누구 기준이냐"를 문서만 보고 답할 수 있어야 한다.
2. **근거 수집.** `diff`는 변경 파일 → 호출부 → 설정·기본값 순, `analysis`는 판단의 근거가 된 코드·쿼리·문서 순. 미확정 사실은 [policies/hypothesis-verification-order.md](../../../policies/hypothesis-verification-order.md) 순서로 먼저 해소한다.
   *완료 기준*: 본문에 쓸 사실마다 `파일:심볼`·쿼리·문서 경로 중 하나를 댈 수 있다. 못 대는 사실은 쓰지 않는다.
3. **직관 초안.** 핵심 **하나**를 토이 데이터 예시로 설명한다. 전부 설명하려 들면 직관이 아니라 목록이 된다.
   *완료 기준*: 코드 인용 없이 예시와 다이어그램만으로 핵심이 성립한다.
4. **본체.** 소스 순서가 아니라 **이해 순서**로 묶는다 — 먼저 알아야 뒤가 읽히는 것이 앞에 온다.
   *완료 기준*: 묶음마다 근거 1개 이상, 묶음 수 5개 이하.
5. **남은 위험과 미해결.** 인수인계용 섹션이다. 모르는 것을 모른다고 쓴다.
   *완료 기준*: 2단계에서 해소하지 못한 의문이 전부 여기 있다.
6. **퀴즈.** 아래 퀴즈 규칙대로 5문항 + 정답표.
   *완료 기준*: 편향 체크 4항 전부 통과.
7. **가지치기.** 삭제 테스트: 한 문장을 지워도 **독자의 이해가 달라지지 않으면** 그 문장은 처음부터 없었던 것이다.
   *완료 기준*: 본문 1,500단어 이내(`wc -w`).
8. **저장·렌더·보고.** `--html`이면 아래 명령으로 HTML을 만든다. 보고에는 산출 경로, 독자, 근거를 못 댄 항목, 남은 위험 개수를 넣는다.

```bash
python3 "$TEAM2_HARNESS_PATH/tools/render_explain_report.py" "$NOTE" "$HTML"
# 사내망·오프라인 공유면 --no-mermaid (다이어그램은 코드블록으로 남는다)
```

## 섹션 규격

| # | 섹션 | 담는 것 | 분량 |
|---|---|---|---|
| 1 | 한 줄 | 무엇을 왜 바꿨나 / 무엇을 알아냈나 | 2~3문장 |
| 2 | 배경 | **2층**: `### 이 도메인을 처음 본다면`(아는 사람은 건너뜀) → `### 이 변경에 한정하면` | 층당 4줄 |
| 3 | 직관 | 핵심 하나 + 토이 데이터 예시 + 다이어그램 | 8줄 |
| 4 | 무엇이 바뀌었나 / 무엇을 알아냈나 | 이해 순서로 묶은 walkthrough. `diff`는 묶음 표, `analysis`는 근거→판단 사슬 | 표 5행 + 불릿 |
| 5 | 남은 위험과 미해결 | 실패 가능 지점, 확인 못 한 것, 후속 필요 | 불릿 3~5 |
| 6 | 퀴즈 | `### Q1.` ~ `### Q5.` + `- A)`~`- D)` 보기 | 5문항 |
| 7 | 정답과 해설 | `\| # \| 정답 \| 해설 \|` 표 (HTML에서 접힌다) | 5행 |

섹션 제목은 위 표 그대로 쓴다 — HTML 렌더러가 필수 섹션으로 검증한다. 2번과 5번이 이 문서의 최대 효용이다. 배경은 "왜 이게 어려운지"에, 남은 위험은 "이걸 물려받으면 뭘 조심할지"에 답한다.

frontmatter: `type: explain`, `title`, `mode`, `reader`, `subject`, `base`, `updated_at`, `summary`. `reader`가 없으면 렌더가 실패한다.

이 표는 [`/ad:code-review`](./code-review.md) 3단계 이해 패스도 참조한다 — 1~5번만 쓰고 퀴즈·정답표·렌더는 제외한다. 표를 고칠 때 code-review 쪽 영향을 함께 본다.

## 퀴즈 규칙

읽었는지 확인하는 장치다. 원안 공개 후 "가장 긴 보기가 정답"이라는 지적이 나왔으므로 편향을 명시적으로 막는다.

- 5문항 4지선다. 각 문항은 **서로 다른 섹션**을 겨냥한다
- 본문을 읽었으면 풀리고 안 읽었으면 못 푸는 난이도. 함정(gotcha)·암기 문제 금지
- 편향 체크: ① 보기 길이 최장-최단 차 20자 이내 ② 한 보기에 정답 절반 초과 쏠림 금지 ③ 같은 문자가 3연속 정답 아님 ④ "모두 맞다 / 없다" 보기 금지
- 해설은 한 줄. 본문의 어느 섹션을 보면 되는지 가리킨다

편향 체크 4항은 **렌더러가 강제한다** — 위반하면 HTML 생성이 종료 코드 2로 실패한다. 자기판정에 맡기면 규칙이 지켜졌는지 알 수 없다. md만 만들 때도 렌더를 한 번 돌려 검증한다.

## 다이어그램

기본: mermaid 2~4개, 섹션당 최대 1개. [policies/mermaid-convention.md](../../../policies/mermaid-convention.md)를 따른다.

- 종류를 재사용한다 — 흐름은 `flowchart TD`, 구성은 `graph TB`, 호출은 `sequenceDiagram`으로 고정하고 문서 안에서 섞지 않는다
- **ASCII 다이어그램 금지.** mermaid 또는 표를 쓴다
- **다이어그램이 보여준 분기를 표나 목록으로 다시 쓰지 않는다.** 한 사실의 정답 위치는 한 곳뿐이다

## 문체와 금지

- 평서형 단정(`~한다`). 확인 못 한 것은 쓰지 않고 5번 섹션으로 보낸다
- 개념 하나에 예시 하나. 코드 인용은 이해에 필요한 최소 줄만
- 언어·제목은 [policies/wiki-document-language-and-title-policy.md](../../../policies/wiki-document-language-and-title-policy.md)를 따른다
- 금지: 리뷰 판정·finding·우선순위 / 진행률·로드맵 / 마케팅 형용사 / 디렉토리 트리
- 실제 비밀·자격증명·회원 식별값·평문 endpoint 금지. 예시는 마스킹한 값으로 만든다 ([policies/security-policy.md](../../../policies/security-policy.md))
- YouTrack, KB, vault, git 커밋, 배포는 건드리지 않는다. 산출물은 로컬 문서 1~2개뿐이다
