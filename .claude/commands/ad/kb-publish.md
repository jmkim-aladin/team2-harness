# YouTrack KB 등록

로컬 문서나 대화에서 확정한 본문을 YouTrack KB에 등록한다. 등록 과정에서 공개 범위와 링크를 정리하고 저장 결과를 확인한다. 기존 KB 전체 정비, 상시 동기화, 원문 재작성은 이 스킬의 범위가 아니다.

아래 단계는 기본 순서다 — 상황에 맞게 조정할 수 있되, KB 생성·수정 전 사용자 확인은 순서와 무관하게 유지한다.

## 입력과 범위

- 원문: 사용자가 지정한 파일 또는 대화의 본문.
- 목적지: 기존 Article URL/ID 또는 새 Article을 만들 상위 KB. 새 문서의 제목·프로젝트는 원문과 상위 KB에서 확인한다.
- 기존 Article을 지정하면 해당 문서에 본문을 등록한다. 목적지가 없으면 게시용 본문을 먼저 준비하고 목적지만 묻는다.
- “등록해줘”, “여기에 초안 넣어줘”처럼 대상과 행위가 명확한 지시는 해당 등록의 승인으로 사용한다. 스킬 호출이나 초안 준비 요청만으로 외부 쓰기 승인을 추정하지 않는다. 승인이 필요한 경우에는 본문과 목적지를 준비한 뒤 묻는다.

지식 배치는 `policies/knowledge-base-policy.md`, 인증과 REST API(`curl`) 사용은 `youtrack/api-guide.md`를 따른다. 경로는 team2 하네스 기준이다.

## 1. 게시용 본문을 만든다

원문 파일을 보존하고 별도 작업본에서 변환한다.

- frontmatter를 제거한다. KB 제목과 같은 첫 H1은 중복 표시되지 않게 제거한다.
- 로컬 위키 전용으로 표시된 근거·판단 이력은 제외한다. 제외 범위는 해당 절의 끝까지이며, 뒤의 다른 절까지 잘라내지 않는다. 외부 참고자료는 유지한다.
- `[[위키 링크]]`, `obsidian://`, 로컬 파일 링크는 그대로 게시하지 않는다. 공개 가능한 KB 대응 문서가 확인되면 그 URL로 바꾼다. 대응 문서가 없으면 링크를 일반 텍스트로 바꾸고, 본문 이해에 필요한 내용이 빠지는지 확인한다. 빠지는 내용이 핵심이면 임의로 생략하지 않고 미결로 남긴다.
- 개인정보·시크릿·운영 실데이터를 게시하지 않는다. 로컬 전용 자료의 내용을 링크 대신 복사해서 노출하지 않는다.
- 본문 의미, 절 구조, 코드·명령 예시, 표와 Mermaid를 유지한다. 초안 요청이면 초안 표시를 유지하며 승인된 표준으로 바꾸지 않는다.

완료 기준: 게시 범위와 제외 항목을 설명할 수 있고, 게시용 본문만으로 필요한 설명을 읽을 수 있다.

## 2. 등록할 본문의 링크를 정리한다

- `§5` 같은 절 참조는 `[5절](Article URL#실제-anchor)`로 바꾸고 한국어 조사를 맞춘다. 대상 제목이 달라진 참조도 함께 맞춘다.
- anchor는 YouTrack 화면의 제목 링크나 목차에서 확인한다. 제목 번호 또는 GitHub의 slug 규칙으로 추정하지 않는다. 한글·영문 혼합 제목과 중복 제목은 특히 확인한다.
- 새 Article이라 URL과 anchor가 아직 없으면 첫 등록에는 제목을 포함한 일반 텍스트 참조를 사용한다. 생성된 Article에서 링크를 확인한 뒤 같은 등록 작업 안에서 링크를 완성한다. 화면 확인이 불가능하면 추정 링크를 넣지 않고 남은 확인 사항을 보고한다.
- 티켓 참조는 `[DEV2-7552](https://aladincommunication.youtrack.cloud/issue/DEV2-7552)`처럼 명시적 Markdown 링크로 만든다. 실제 원문의 프로젝트와 번호를 사용한다.
- 기존 정상 URL을 보존한다. 이미 링크인 텍스트를 중첩 변환하지 않는다. 코드 블록·인라인 코드·Mermaid 안의 참조 예시는 치환 대상에서 제외한다.

근거: 2026-09-07 KB 등록에서 절 참조가 일반 텍스트로 남았고, 한국어 조사가 붙은 티켓 번호의 자동 링크가 동작하지 않았다. 같은 문서에서도 제목에 따라 anchor가 `5`, `9-api`, `10-ai`로 달랐다. 이 값은 다른 문서에 재사용하는 규칙이 아니다.

완료 기준: 변환한 참조마다 실제 대상이 대응되고, 확인하지 못한 anchor는 깨진 링크 대신 일반 텍스트로 남아 있다.

## 3. 등록하고 다시 읽어 확인한다

1. 기존 Article은 본문·수정 시각·제목·부모·프로젝트·공개 범위를 읽어 보관하고 게시용 본문과 비교한다. KB에서만 추가된 내용을 발견하면 자동으로 덮어쓰지 말고 충돌 부분을 정리한다. 새 Article은 지정한 상위 KB와 공개 범위를 확인한다.
2. 승인된 대상에만 등록한다. 기존 문서는 `content`만 수정하며 제목·부모·프로젝트·공개 범위는 별도 변경 지시가 있을 때만 바꾼다. 쓰기 직전 다시 조회해 작업 중 변경이 생겼으면 재비교한다. 이 확인을 원자적 동시성 보장으로 설명하지 않는다.
3. 응답이 불명확하면 재시도 전에 등록 여부를 조회한다. 생성 요청을 바로 반복하여 중복 문서를 만들지 않는다.
4. 저장한 Article을 다시 조회해 본문 일치와 목적지·메타데이터를 확인한다. 화면을 사용할 수 있으면 제목 이동과 Mermaid 등 렌더링도 확인한다. API 저장 확인을 화면 동작 확인으로 보고하지 않는다.

결과는 KB 링크, 제외·변환한 항목 요약, 저장 확인 결과와 남은 확인 사항으로 짧게 보고한다. 별도 지시 없이 로컬 원문을 수정하거나 커밋하지 않는다.
