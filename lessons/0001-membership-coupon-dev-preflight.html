배포 성공과
발급 가능은 다르다

DEV2-8628의 9월 설정을 이용해 안전장치 SP 2개를 반영하고, 이미 발급에 사용된 월별 객체 3개까지 실제 발급 없이 통합 검수하는 방법을 익힌다.

핵심 구분은 소스 설정과 DB 마스터 설정이다. 소스에 NType을 잘 넣어도 dev의 CouponNType과 Event가 없거나 기간이 틀리면 발급하면 안 된다.

왜 DDL 성공만으로 부족할까? SQL Server는 프로시저 생성 시 구문을 확인하지만 참조 객체는 첫 실행 시점에 해결될 수 있다. 그래서 CREATE OR ALTER 성공 뒤 반드시 실행 테스트가 필요하다. Microsoft CREATE PROCEDURE 문서

발급 SP는 후보를 임시 테이블에 만든 뒤 설정을 검사한다. 실제 쿠폰번호 생성은 쓰기 게이트 뒤에 있다.

운영 안전장치 2개 선택 반영 — 승인된 반영 시간에만 펼치기

지금은 이미 dev에 반영되어 있으므로 다시 실행할 필요가 없다. 운영에서는 전체 deploy.sh가 아니라 안전장치 SP 2개만 백업 후 순서대로 반영한다. sqlcmd -b는 SQL 오류를 셸 실패로 전달한다.

cd "${SHOP_DB_SCRIPT_PATH:?SHOP_DB_SCRIPT_PATH를 설정하세요}"

db_server="${COOL_DEV_DB_HOST:?COOL_DEV_DB_HOST를 설정하세요}"
db_user="${COOL_DEV_DB_USER:?COOL_DEV_DB_USER를 설정하세요}"
db_password=$(security find-generic-password -s 'cool-dev' -a "$db_user" -w)
export SQLCMDPASSWORD="$db_password"

object_names=(
  Coupon_NewMake_MembershipMontly
  Coupon_NewMake_MembershipMontly_Preflight
)
target_files=(
  databases/WebCatalog/StoredProcedures/Coupon_NewMake_MembershipMontly.sql
  databases/WebCatalog/StoredProcedures/Coupon_NewMake_MembershipMontly_Preflight.sql
)

rollback_dir=$(mktemp -d /tmp/dev2-8924-rollback.XXXXXX)
backup_failed=0
for object_name in "${object_names[@]}"; do
  sqlcmd -S "$db_server" -U "$db_user" -d 'WebCatalog' -C -b -h -1 -W -y 0 \
    -Q "SET NOCOUNT ON; SELECT OBJECT_DEFINITION(OBJECT_ID(N'dbo.${object_name}'));" \
    > "$rollback_dir/${object_name}.sql" || {
    backup_failed=1
    break
  }
  test -s "$rollback_dir/${object_name}.sql" || {
    backup_failed=1
    break
  }
done
echo "rollback: $rollback_dir"

deploy_failed=0
if [ "$backup_failed" -eq 0 ]; then
  for deploy_file in "${target_files[@]}"; do
    rg -q '^CREATE OR ALTER (FUNCTION|PROCEDURE)' "$deploy_file" || {
      echo "CREATE OR ALTER 확인 실패: $deploy_file"
      deploy_failed=1
      break
    }
    echo "[deploy] $deploy_file"
    sqlcmd -S "$db_server" -U "$db_user" -d 'WebCatalog' -C -b \
      -i "$deploy_file" || {
      deploy_failed=1
      break
    }
  done
else
  echo '롤백 정의 저장 실패: 배포하지 않음'
fi

unset SQLCMDPASSWORD db_password db_user db_server
test "$backup_failed" -eq 0 && test "$deploy_failed" -eq 0
기대: 대상 2개가 모두 [deploy]로 표시되고 마지막 명령이 성공한다. 하나라도 실패하면 그 자리에서 다음 파일 반영을 멈춘다.

직접 확인 3 — 프리플라이트

객체는 이미 dev에 반영되어 있으므로 이 단계부터 바로 재현할 수 있다. 오류를 잡아 번호와 쿠폰 건수 변화를 한 행으로 본다.

db_server="${COOL_DEV_DB_HOST:?COOL_DEV_DB_HOST를 설정하세요}"
db_user="${COOL_DEV_DB_USER:?COOL_DEV_DB_USER를 설정하세요}"
db_password=$(security find-generic-password -s 'cool-dev' -a "$db_user" -w)
export SQLCMDPASSWORD="$db_password"

sqlcmd -S "$db_server" -U "$db_user" -d 'WebCatalog' -C -b -W -s '|' -Q "
SET NOCOUNT ON;
DECLARE @Before bigint=(
  SELECT COUNT_BIG(*) FROM dbo.Coupon
  WHERE NType IN (54643,54644,54645,54646,54647,54648,54649,54650,54651,54652)
);

BEGIN TRY
  EXEC dbo.Coupon_NewMake_MembershipMontly_Preflight
    @TargetYearMonth='202609',
    @ExpectedMembershipNTypes=N'54643,54644,54645,54646,54647,54648,54649,54650,54651,54652';
END TRY
BEGIN CATCH
  SELECT ERROR_NUMBER() ErrorNumber,
    ERROR_MESSAGE() ErrorMessage,
    @Before BeforeCount,
    (SELECT COUNT_BIG(*) FROM dbo.Coupon
      WHERE NType IN (54643,54644,54645,54646,54647,54648,54649,54650,54651,54652)) AfterCount;
END CATCH;"

unset SQLCMDPASSWORD db_password db_user db_server
현재 dev 기대: 52105 / 멤버십 쿠폰 타입 또는 이벤트 오류 / 0 / 0
이 결과가 왜 성공인가? 마스터가 없는데 발급을 진행했다면 장애다. 52105로 쿠폰번호 생성 전에 멈췄고 전후 쿠폰 건수가 같으므로 안전장치가 목적을 달성했다.

직접 확인 4 — 운영 통합 검수

통합 검수 SQL은 DB에 배포하는 객체가 아니라 작업자 PC에서 실행하는 읽기 전용 스크립트다. 안전장치 SP 2개를 반영한 뒤, 기존 월별 객체 3개와 마스터까지 한 번에 확인한다.

cd "${SHOP_DB_SCRIPT_PATH:?SHOP_DB_SCRIPT_PATH를 설정하세요}"

# 승인된 운영 접속 절차로 설정한다. 비밀번호를 명령이나 파일에 직접 적지 않는다.
db_server='<승인된 운영 DB 서버>'
db_login='<본인 운영 DB 계정>'
export SQLCMDPASSWORD='<Keychain에서 불러온 비밀번호>'

sqlcmd -S "$db_server" -U "$db_login" -d WebCatalog -C -b -W \
  -v TargetYearMonth=202609 \
     ExpectedMembershipNTypes="54643,54644,54645,54646,54647,54648,54649,54650,54651,54652" \
     ExpectedMobileNType=54643 \
     ExpectedCoffeeNType=54653 \
     ExpectedMembershipEventId=313942 \
     ExpectedCoffeeEventId=313944 \
     ExpectedGradeUpNTypes="54643,54652,54651,54650,54649" \
  -i scripts/verify-membership-coupon-month.sql

unset SQLCMDPASSWORD
최종 행검수 대상
preflight PASS일반 NType 10종·만료일·월 문구·활성 기간
no-write PASS대상 쿠폰 건수 전후 동일
exception-function PASS일반·모바일·커피 예외 함수
master-data PASS일반·커피 CouponNType과 Event 연결
coffee-mapping PASS202609 → 54653 운영 정의
grade-up-event PASSEvent 313942의 발급 NType 목록
합격: 명령 종료 코드 0 + 최종 PASS 6개 + no-write 전후 건수 동일. 중간에 NType별 OK 행이 보여도 최종 PASS 표가 없거나 Msg 오류가 있으면 실패다.
격리 환경에서 검증한 근거 SQL Server 2022 Docker를 운영과 같은 한국어 서버 Collation으로 올리고 실제 소스 객체 5개를 반영했다. 정상 마스터에서는 PASS 6개와 쿠폰 0→0, 커피 Event 연결을 틀리게 만든 경우에는 52313 차단을 확인했다.
52300번대가 의미하는 것 52300~52307은 검수 입력·필수 객체, 52308은 데이터 변경, 52309~52311은 예외 함수, 52312~52313은 마스터/Event, 52314~52316은 커피·등급변경 운영 정의 오류다. 하나라도 나오면 실제 배치를 실행하지 않는다.
여기서 멈출 것 통합 검수가 모두 통과해도 @Proc=1,@TestCase=0을 즉시 실행하지 않는다. 실제 쿠폰번호 생성과 Coupon INSERT는 승인된 월말 정규 배치 일정에서만 시작한다.
