# 위키 검토를 AI가 먼저 처리하는 방법

목표는 새 보고서를 늘리는 것이 아니라 기존 검토 요청을 근거로 해결하는 것이다. 사용자는 2026-09-27 위키·소스로 검증 가능한 일을 AI가 자체 처리하도록 지시했다. 정책 선택과 실행 승인은 이 지시로 자동 승인되지 않는다.

## 한 번의 작업

기본: 한 번에 기존 큐에서 3건 이내를 검토한다. 중복 문서·과거 검토부터 원본 업무에 연결하고, 아직 검토하지 않았으며 현재 환경에서 근거에 접근할 수 있는 항목을 우선한다. 보류 항목은 새 근거가 생겼을 때 다시 본다. 사용자의 긴급 요청이 있으면 순서를 조정한다.

1. `/workspace/team2/AGENTS.md`, `configs/discord-agent-profiles.yaml`, `docs/discord-agent-orchestration-guide.md`의 AI 검토 기준을 읽는다. 보드는 `/workspace/team2-vault/wiki/projects/agentic-os/hermes-decision-board.json`이다.
2. 원본 위키의 문제와 남은 확인을 읽는다. 기존 결정 기록과 접근 가능한 소스의 현재 버전·이력을 대조한다. 동작 판정에는 해당 환경에서 실행할 수 있는 테스트를 사용한다.
3. 확인한 범위만 원본 노트의 `generated:agent-review-{날짜}` 블록에 짧게 기록한다. 기준 코드 버전, 방법, 결과, 미확인 범위, 다음 행동을 남긴다. 같은 주제의 일별 요약을 별도 카드로 반복 생성하지 않는다.
4. 사실 확인이나 오래된 검토 요청이 해소됐으면 해당 검토 상태를 정리한다. 실제 정책 결정이나 실행 승인이 남으면 질문·이유·추천·근거를 갖춘 사용자 요청을 준비한다. 검증하지 못한 것은 검증 완료로 바꾸지 않는다.

## 기록과 권한

- 허용: 로컬 위키·하네스·마운트된 소스 읽기, 외부 상태를 바꾸지 않는 테스트, 위키의 검토 근거·다음 행동·사실 검토 상태 갱신.
- `agent_reviewed_at`에는 검토일, `agent_review_result`에는 검증 완료·부분 확인·근거 접근 불가 등 결과, `agent_next_action`에는 AI가 이어서 할 일을 남긴다. 검토와 실제 실행의 혼동을 막기 위해 이 값은 업무 완료나 운영 배포 상태와 구분한다.
- `review_state: reviewed`, `decision_status: none`은 해당 검토 요청이 근거로 해소됐을 때만 사용한다. 필요한 승인이 남아 있으면 유지한다. 원본의 과거 사실과 결정 이력은 보존한다.
- 위키 사실 검토와 실행 승인의 경계를 지키기 위해 `ticket_status`, YouTrack 공식 상태, `status: canonical`/`confirmed` 승격은 이 작업에서 변경하지 않는다. DB/SP 쓰기, 운영 배포, 커밋·푸시·PR·KB 변경도 수행하지 않는다.
- 컨테이너에서 소스가 보이지 않으면 접근 불가로 기록한다. 파일 부재를 구현 부재로 단정하거나 권한·마운트를 임의 확장하지 않는다. 기존 근거로 진행할 수 있는 다른 항목을 먼저 처리한다.
- 기계적인 링크 확인·정적 검사와 실제 서비스 동작 검증은 구분한다. 사용자 요청에는 실제로 사용자 판단이 필요한 이유가 있어야 한다.

## 결과와 인계

기본: 한국어로 확인한 건, 해결한 검토 요청, 남은 AI 작업을 짧게 보고한다. 실제 결정·승인이 필요한 항목만 질문한다. 일반 검토 완료에 사용자 확인을 다시 요구하지 않는다.

원본 갱신 후 보드·사용자 화면은 기존 knowledge board cycle이 재생성한다. Discord 전송과 Kanban 동기화도 기존 실행 경로를 사용한다. 큐를 만든 사실과 실제 에이전트 실행·검증 결과는 구분해서 보고한다.
