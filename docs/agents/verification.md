# DEV2 완료·인계 검증 증거 계약

코드·문서·분석 작업의 완료 보고와 세션 인계에서 사용한다. 기존 티켓/계획/repository evidence가 원장이며, 이 문서는 그곳에 남길 내용의 규격이다.

```markdown
- 검증 대상: {repo/worktree, base·head revision, 미커밋 변경 유무와 해당 diff/산출물 포인터}
- 검증 증거: {실행 시점·환경·기대값·관찰 결과를 담은 기존 evidence 링크}
- 현재와의 차이: {검증 이후 변경된 코드·설정·데이터, 없으면 없음}
- 다음 행동: {완료한 작업을 반복하지 않고 이어갈 첫 단계}
```

- 코드 작업이 아니면 revision 대신 산출물 버전·digest 등 적합한 식별자를 사용한다. HEAD가 같아도 미커밋 변경과 환경이 다르면 같은 검증 대상이 아니다.
- 원본 파일·diff·실행 결과를 확인한다. delegate의 성공 요약, mtime, CI의 녹색 표시만으로 해당 완료 조건을 입증했다고 쓰지 않는다.
- 실행 실패·환경 막힘·관찰 불가는 미확인 범위와 이유를 남긴다. 정적 확인을 실행 확인으로 바꾸지 않는다. 부족한 근거의 처리는 해당 작업의 기존 완료 기준을 따른다.
- 재개 시 원장과 현재 상태를 대조해 완료/대기를 구분한다. 검증 대상이 바뀐 범위는 재검증하며 `patch-id` 일치만으로 런타임 증거를 승계하지 않는다.
- 중요한 채택·기각·전환만 기존 진행 기록에 `판단 → 이유 → 증거 → 결과`로 남긴다. 서비스 코드에 묶인 증거는 서비스 repo, 운영·티켓 진행은 [지식 경계](../../policies/knowledge-base-policy.md)에 따라 둔다.
- 개발 검증, 별도 QA, 배포 후 확인을 구분한다. 서비스 실행법은 [서비스 검증 계약 템플릿](../../templates/service-harness/VERIFICATION.md.tmpl)과 해당 서비스의 실제 계약을 참조한다.
