# 반증 검토 (doubt review)

[`/ad:eng-review`](../../.claude/commands/ad/eng-review.md) 6단계. 강도가 위험([harness-guide.md](../harness-guide.md) §작업 플로우 2. 개발)일 때만 쓴다. 섹션 리뷰는 작성자의 추론을 따라가며 판정하고, 반증 검토는 그 추론 없이 산출물만 보고 결정을 깨뜨리려 한다 — 작성자의 논리를 읽은 검토자는 같은 맹점을 물려받는다.

## 대상 고르기

- 되돌리기 비싼 결정만: 공유 DB 스키마·데이터 이관, 멱등키·지급·차감 경로, 인증·권한 경계, 외부 계약(API·이벤트 스키마), 운영 데이터 일괄 변경
- 결정마다 계약 한 줄: `{결정} — 깨지면 {피해}`. 예: `쿠폰 지급은 지급 이벤트 ID unique로 1회만 — 깨지면 이중 지급이 정산까지 번진다`
- 1~2개. 그보다 많으면 스코프가 크다는 신호다 — Step 0으로 돌아가 분할을 제안한다

## 검토자에게 주는 것

| 준다 | 주지 않는다 |
|---|---|
| 산출물 — 티켓 노트 `구현 계획`(완료 조건·슬라이스, 같은 벤더 검토자면 경계 포함), 관련 코드 경로, 스키마·SP 이름 | 작성자의 주장·추론·대안 비교 과정 |
| 계약 — 결정 한 줄 + 깨지면 생길 피해 | 섹션 리뷰 판정·추천안, 대화 이력 |

검토자 — 기본: `HERDR_ENV=1`이면 [`/ad:orchestration`](../../.claude/commands/ad/orchestration.md)으로 다른 벤더 peer(Codex)의 fresh context, 아니면 새 컨텍스트 서브에이전트(Agent) 또는 eng-review §5의 교차 모델 CLI. 다른 벤더를 먼저 고르는 이유는 같은 모델의 맹점까지 피하기 위해서다.

Codex 호스트가 caller면 다른 벤더는 Claude Code다 — `HERDR_ENV=1`이면 `/ad:orchestration`의 Claude peer, 아니면 eng-review §5의 `claude -p --allowedTools Read Grep Glob`(읽기 전용), 둘 다 안 되면 새 컨텍스트 Codex 서브에이전트. 아래 데이터 경계는 방향과 무관하게 같다.

다른 벤더 검토자(Codex·Claude peer, 교차 모델 CLI)에게는 [교차 모델 리뷰 데이터 경계](../code-review/cross-model.md) §프롬프트를 그대로 적용한다 — 완료 조건·슬라이스·관련 코드만 보내고 노트 경계 절·티켓 본문·팀 정책은 보내지 않는다. 대상 repo가 팀 소유가 아니면 eng-review §5 외부 의견 게이트대로 실행 전 사용자에게 확인한다. 근거: 반증에는 산출물만 있으면 되고, 업무 맥락·하네스 구조를 다른 벤더로 보낼 이유가 없다.

기본 프롬프트:

```
너는 이 결정이 틀렸음을 보이는 반증자다. 검증이 아니라 반증이 목표다.
아래 계약과 산출물만 본다. 계약이 깨지는 구체 시나리오(입력·순서·동시성·장애·데이터 상태)를 찾고,
시나리오마다 산출물의 어느 지점(파일·슬라이스·완료 조건)이 그것을 막지 못하는지 댄다.
못 찾으면 "반증 실패"와 시도한 공격면을 적는다. 칭찬·요약 없이 시나리오만.

계약: {결정} — 깨지면 {피해}
산출물:
<구현 계획(다른 벤더면 완료 조건·슬라이스만) + 코드 경로>
```

## 라운드

- 한 라운드 = 반증 제시 → 메인이 산출물을 고치거나 막는 지점을 산출물에 명시 → 갱신된 산출물로 새 컨텍스트 검토자에게 재반증. 같은 검토자를 이어 쓰면 앞 라운드의 대화가 작성자 주장 역할을 한다
- 반박은 산출물 수정으로 한다 — 대화로만 반박하면 다음 검토자에게 전달되지 않고, 구현자도 그 근거를 못 본다
- 상한 3라운드. 3라운드 뒤에도 반증이 살아 있으면 미결 결정으로 사용자에게 올린다 — 라운드 반복은 수렴의 증거가 아니다

## 기록

티켓 노트 `결정 패킷`에 결정마다 한 줄:

`반증 검토: {결정} — {N}라운드 / {살아남은 반증 요약 | 반증 실패(공격면 요약)} / 산출물 변경: {슬라이스·완료 조건 변경 또는 없음}`
