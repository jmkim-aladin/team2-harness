# Codex CLI 마우스 SGR 입력 유출 조사

- 조사일: 2026-11-12 (KST)
- 공통 task_id: `TASK-20261112-1de78410ef7c`
- 대상: macOS Codex CLI `0.167.1`, Herdr가 없는 별도 PTY 재현 포함

## 검증함

1. 확인한 공개 이슈 중 사용자 화면과 같은 증상을 다루는 최신 건은 [openai/codex #60814](https://github.com/openai/codex/issues/60814)다. 2026-11-11 등록·현재 `OPEN`이며, Codex CLI 0.167.1/macOS에서 빠른 휠 스크롤 시 `<65;103;75M` 같은 SGR 마우스 리포트 꼬리가 composer에 들어오고 실행 중인 turn을 중단할 수 있다고 보고한다. 이슈 작성자는 Codex가 고정한 Crossterm fork와 Unix read-boundary를 재현 코드로 좁혔고, `Parser::buffer_external_input()`을 두 Unix reader에 사용하자는 후보 패치와 회귀 테스트를 제시했다. 이슈 본문은 후보 패치 기준 두 backend 테스트가 `147 passed, 0 failed, 7 ignored`라고 기록하지만, upstream에 머지됐다는 표시는 없다.

2. 같은 원인을 더 이른 버전에서 확인한 [#55134](https://github.com/openai/codex/issues/55134)은 현재 `OPEN`이다. 0.163.0/Ghostty에서 시작했으며, [OpenAI 기여자 계정의 triage 댓글](https://github.com/openai/codex/issues/55134#issuecomment-6391689500)은 0.163.0과 `main`이 공통으로 고정한 Crossterm revision `ed1cdab3`에서 intact report는 wheel event가 되지만 `ESC` 직후 1ms 간격으로 분리하면 `Esc` 2회와 literal `[<64;125;28M...`이 나왔다고 기록했다. 해당 댓글은 `(response from codex)`라고 명시돼 있다. 작성자의 2026-11-10 코멘트는 0.167.0에서도 재현된다고 한다. 이슈의 다른 댓글에는 macOS Terminal.app 사용자도 동일한 `Conversation interrupted`와 `[<65;196;41M`을 보고했다.

3. [#57445](https://github.com/openai/codex/issues/57445)은 0.164.0/cmux의 동일한 wheel-tail + active-turn interruption 보고로, 2026-11-09 닫혔지만 원인 해결을 뜻하지 않는다. maintainer는 parser 단독으로 `ESC` 분리 시 동일한 결과를 재현했고, 물리 마우스에서 실제 분리가 일어났는지는 확인하지 못했다고 남겼다.

4. 최초 보고 [#49184](https://github.com/openai/codex/issues/49184)은 0.157.1/cmux에서 같은 증상을 기록했고, 2026-10-02 `0.159.0에서 수정 예정`이라는 maintainer 코멘트로 닫혔다. 이후 #57445와 #60814가 0.164.0·0.167.1에서 재현되므로, 해당 코멘트는 현재 버전에서의 해결 보장이 아니다. Windows 계열의 유사 입력 유출도 [#49126](https://github.com/openai/codex/issues/49126)과 [#48407](https://github.com/openai/codex/issues/48407)에 보고됐다.

5. 로컬 별도 PTY에서 Codex CLI 0.167.1을 모델 호출 없이 실행한 결과, 완전한 `ESC[<65;111;62M` 패킷과 CSI suffix 분할은 정상 처리됐지만 `ESC`와 나머지를 1·5·30·100ms 간격으로 분리한 네 조건 모두 `BEGIN_[<65;111;62M_END` 형태로 composer에 남았다. 같은 하네스에서 Claude Code 2.1.322는 기본 화면과 NO_FLICKER 전체 화면의 whole/split-ESC(1·5·30·100ms)/split-CSI 조건을 모두 통과해 누출이 없었다. 원본 근거는 `/tmp/terminal-mouse-TASK-20261112-1de78410ef7c/codex-codex-fullscreen-results.json`, `claude-default-results.json`, `claude-fullscreen-results.json`, `claude-probe.py`다. 활성 turn 중단과 실제 자연 스크롤의 패킷 분할은 두 제품 모두 아직 시험하지 않았다. 이 비교는 Herdr 공통 전달층보다 Codex 입력 파서 경로를 우선 의심하게 한다.

6. Codex 0.167.1이 고정한 [Crossterm revision `ed1cdab3`](https://github.com/openai-oss-forks/crossterm/tree/ed1cdab335221515706178d68495bba2aed1924f)의 Unix reader는 짧은 read를 `parser.advance(..., read_count == TTY_BUFFER_SIZE)`로 넘긴다([mio.rs](https://github.com/openai-oss-forks/crossterm/blob/ed1cdab335221515706178d68495bba2aed1924f/src/event/source/unix/mio.rs), [tty.rs](https://github.com/openai-oss-forks/crossterm/blob/ed1cdab335221515706178d68495bba2aed1924f/src/event/source/unix/tty.rs)). 파서의 단독 `ESC` 경로는 `KeyCode::Esc`를 즉시 만들고([parse.rs](https://github.com/openai-oss-forks/crossterm/blob/ed1cdab335221515706178d68495bba2aed1924f/src/event/sys/unix/parse.rs)), Codex TUI는 실행 중 `Esc`를 interrupt 판단에 사용한다([bottom_pane/mod.rs](https://github.com/openai/codex/blob/rust-v0.167.1/codex-rs/tui/src/bottom_pane/mod.rs)). 따라서 `ESC` 분리 → 가짜 Esc → turn 중단 + 나머지 문자 유입이라는 설명이 코드와 재현 결과에 맞는다.

7. 2026-11-12 현재 `openai-oss-forks/crossterm` `master`도 두 Unix reader에서 여전히 `parser.advance(..., read_count == TTY_BUFFER_SIZE)`를 사용하며, `openai/codex` `main`의 [`codex-rs/Cargo.lock`](https://github.com/openai/codex/blob/main/codex-rs/Cargo.lock)은 여전히 `ed1cdab3`를 가리킨다. `buffer_external_input` 후보 패치를 적용한 Codex PR은 GitHub PR 검색과 #60814 timeline에서 확인되지 않았다.

## 확인 못 함

- 사용자의 실제 Herdr 세션에서 휠 입력의 raw PTY 바이트가 `ESC`와 suffix로 분리되는 순간.
- 모델 호출 중인 실제 Codex 세션에서 같은 입력이 turn을 중단하는 장면을 로컬 probe로 재현하는 것. 현재 probe는 idle 상태다.
- 후보 패치가 upstream 어느 release에 들어갈지 또는 별도 workaround가 배포됐는지.

## 결정 필요

- #60814를 현재 증상의 대표 upstream 이슈로 추적한다.
- #60814 본문은 `--no-alt-screen`을 수동 시험의 완화책으로 기록했지만, 이번 로컬 시험은 해당 옵션을 켠 상태에서도 ESC 분리 시 누출됐다. 따라서 이 옵션을 검증된 해결책으로 채택하지 않는다.
- 실제 turn 중단이 재현되면 issue #60814에 Herdr·Ghostty·Codex 버전과 raw PTY 분할 증거를 추가할지 결정한다.
