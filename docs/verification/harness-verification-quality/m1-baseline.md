## 현재까지의 관찰

초기 v1의 두 실행에서 설명문은 모두 기대한 문제를 짚었다. 문서 오타는 정확히 수정했고, 할인 기대값이 구현식을 복사했다는 점, 표본 중복과 분모 불일치, 환불 이벤트 중복 차감을 식별했다. 그러나 schema 판정은 첫 실행 3/4, 두 번째 실행 1/4 사례만 PASS였다.

- v1 첫 실행: 정산 사례 본문은 완료 보류인데 `ready=true`였다.
- v1 두 번째 실행: 할인·정산 본문은 완료 보류인데 `ready=true`였다. 정산 응답은 명시적으로 “자료 검토는 완료했습니다”라고 써 필드의 의미를 다르게 해석한 점을 보여 줬다.
- v1 두 번째 문서 사례: 마지막 개행 누락과 “제시한 본문을 파일에 반영” 안내가 정확 일치·빈 추가 작업 assertion에 걸렸다. 이것만으로 불필요한 테스트나 과잉 절차를 요구했다고 볼 수 없다.
- v1의 `ready`·개행·추가 작업 의미는 후보 출력 계약에 충분히 정의되지 않았다. 이 결과를 잘못된 배포 승인이나 팀 하네스 결함의 증거로 단정하지 않는다. 초기 실패와 assertion은 그대로 보존했다.
