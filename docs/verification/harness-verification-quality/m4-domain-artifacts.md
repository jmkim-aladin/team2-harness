# 업무별 산출물 시험 — M4 실행·채택 계약

작업 ID: `TASK-20261104-4560e95349bc`. M3 정산 응답의 주문별·전체 합계 혼동을 계기로, 데이터 정합성 관점에 실제 정산 대사표를 맡길 가치가 있는지 시험한다. 위키가 진행 원장이며 이 문서는 입력·비교·채택 기준의 원본이다.

## 범위와 불변조건

- 기존 위험 강도 데이터 정합성 관점의 읽기 전용 산출물만 시험한다. 실제 PR 리뷰를 실행하거나 서비스 코드·DB·외부 시스템을 변경하지 않는다. 새 페르소나·스킬·자동 투입 범위·권한은 추가하지 않는다.
- reviewer 기본 프로필 `gpt-6-sol`·`xhigh`를 동일하게 사용하는 fresh CLI A/B를 새로 실행한다. M3의 worker 출력은 발견 계기이며 프로필이 달라 이번 대조군으로 쓰지 않는다.
- 같은 합성 입력·공통 요청·schema·예산·모델·설정에서, B에만 정산 대사표 산출물 지시를 추가한다. 후보는 역할극 대신 원자료를 읽고 대조표를 작성한다. 다른 후보·기존 응답·정답·평가 기준은 제공하지 않는다.
- 결과의 `arithmetic_ok`는 제공된 정산 수치가 입력 계약에 맞는지다. 실제 구현·테스트·배포 완료는 별도 미확인으로 둔다. schema는 A/B 공통이며 금액 정답을 포함하지 않는다.

## 채택 기준과 실행 상한

- 먼저 세 사례의 A/B를 한 번씩 실행한다(6회). B가 모든 사례를 정확히 처리하고, 정상 입력 오탐 없이 A의 실제 누락·오류를 하나 이상 해소하면 그 사례의 A/B만 한 번 더 실행한다(최대 8회).
- 재실행에서도 차이가 재현되고 추가 비용이 해당 실패 검출에 비례하면 기존 data-integrity 출력에 조건부 참고 한 줄을 채택할 수 있다. 모든 리뷰의 필수 표로 만들지 않는다.
- A도 이미 같은 오류를 검출하거나 차이가 재현되지 않으면 기본 규칙 반영을 **보류**한다. B에 계산 오류·새 오탐이 있으면 이번 후보는 **기각**한다. 추가 검출력이 없는 것을 성과로 만들지 않는다.
- 시간, prompt/output 크기, CLI가 보고한 usage를 관찰 범위대로 남긴다. 사람의 가독성·작업 시간과 전체 서비스의 결함 검출률은 측정하지 않는다.
- 보류·기각도 원본·이유·재검토 조건을 기록하면 이 단계의 완료다. 이후 반복 실행을 계속 요구하지 않는다.
